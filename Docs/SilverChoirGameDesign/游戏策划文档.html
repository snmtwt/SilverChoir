文档目标

这套文档先建立完整目录和可填写区域，不预设尚未确认的玩法结论。正式内容应优先写清玩家体验、规则边界、关键参数、异常处理和验收方法。
服务对象策划、程序、美术、音频、测试以及需要了解设计边界的协作者。
内容粒度主文档记录可执行的设计规则；具体表格、配置和资源清单可从章节继续链接。
维护原则先记录已决定内容，再记录假设和待验证问题；避免把讨论中的想法写成既定规则。
状态标记建议使用“草案 / 待验证 / 已确认 / 已实现 / 已废弃”。

推荐填写顺序

  1. 先完成“设计愿景与范围”和“核心循环”，固定项目方向。
  2. 再明确战略层、单位小队和战术层之间的输入输出关系。
  3. 用内容目录和数值章节定义需要生产多少内容、如何验证强度。
  4. 最后补齐表现、生产、测试、风险和变更记录，形成可执行基线。

填写规范

  • 每条规则说明触发条件、执行结果和边界情况。
  • 每个关键数值注明单位、默认值、允许范围和调整目的。
  • 每个系统说明玩家可见反馈，不只描述后台数据变化。
  • 未确认内容保留“待验证”状态，并写明验证方法。
  • 跨章节规则只确定一个权威来源，其余章节使用链接引用。

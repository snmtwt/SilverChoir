读档与生命周期

清理 API 是深度清理。它不仅从子系统移除地图，还会同步解除展示、清空瓦片/棋子容器并使旧对象失效。

深度清理顺序

  1. 从默认槽位、GUID Map 与活动 3D 地图注册表移除目标地图。
  2. 逐个移除棋子数据，向瓦片和展示层发送移除通知。
  3. 解绑 3D 瓦片与 3D 地图，销毁其展示内容。
  4. 清空瓦片的棋子容器、地图关联与地图的瓦片索引。
  5. 广播 OnMapDataCleared；2D 控件据此自动解除绑定。
  6. 使地图、瓦片、棋子对象的 GUID/ID、所属关系与展示引用失效。

推荐读档流程

ClearAllMapData
  -> 读取存档中的地图配置与玩法状态
  -> CreateMapData
  -> 恢复地图/瓦片子类字段
  -> AddPieceToTile... 恢复棋子
  -> AGSMMap3D / UGSMMapWidget2D 注册并绑定新数据

若存档需要稳定地图身份，保存创建时返回的 MapGuid 或建立自己的存档键映射。瓦片用 TileId，棋子用 PieceGuid。

旧引用的处理

深度清理后，旧 UObject 仍可能被蓝图变量、异步回调或 UI 缓存暂时引用，但它不再表示有效数据。使用以下函数判断：

  • UGSMMapData::IsMapDataValid
  • UGSMTileData::IsTileDataValid
  • UGSMPieceData::IsPieceDataValid
不要只依赖 IsValid(Object)。对象可能仍是可访问 UObject，但其 GSM 身份已失效。

默认地图替换

调用 CreateMapData(..., true, ...) 创建新的默认地图时，已有默认地图会先被深度清理，并记录日志。未勾选默认地图而默认槽为空时，新地图会自动成为默认地图，确保默认地图始终可用。

GameInstance 结束

UGSMMapSubsystem::Deinitialize 会调用 ClearAllMapData，因此 GameInstance 关闭时同样会执行完整解除绑定流程。

掩体状态与动画蓝图

交互组件管理占用和进入过程；动画蓝图使用自己的枚举记录贴靠后的姿态。这个枚举和 CoverState 变量均为蓝图资产内容。

2026.09.18 查询结构更新：当前按行为 → 装备 → 动作分层，WeaponPose 已迁移为 EquippedWeaponType；旧表格路径与截图用于说明原功能。当前编辑入口及迁移说明见第 13 章。

本页内容：找到枚举和变量设置探出方向什么时候更新如何用于动画验证结果
01 / BLUEPRINT DATA

找到枚举和变量

  1. 在内容浏览器打开 /Game/MVTest/SmartObject/CoverQuery/E_HMSCoverState。这是普通的蓝图枚举，可以在编辑器里修改。
  2. 打开 /Game/MVTest/Famale/ABP_Famale，在“我的蓝图”变量列表搜索 CoverState，分类为 HMS | 掩体。
  3. 变量类型为 E_HMSCoverState，默认值为“未进入掩体”。它没有添加到 C++ 动画实例基类。
枚举值含义
未进入掩体尚未完成贴靠，或已经退出交互。
右侧站立已经贴靠；当前配置允许从右侧以站立姿态探出。
右侧蹲伏已经贴靠；当前配置为右侧蹲伏。
左侧站立已经贴靠；当前配置为左侧站立。
左侧蹲伏已经贴靠；当前配置为左侧蹲伏。

判断是否进入掩体，可以直接比较 CoverState != 未进入掩体，无需再维护一个可能不同步的布尔变量。这个枚举一次表示一种姿态；如果以后需要同时表达多个可用探出方向，可以另外增加能力标签集合。

02 / SLOT CONFIGURATION

由插槽设置探出方向

角色从哪个方向跑过来，与贴靠后允许向哪边探出是两个不同的设置。当前实现读取实际占用插槽上的 Runtime Tags，再由 ABP_Famale 的 RefreshCoverState 函数映射到枚举。

  1. 打开 /Game/MVTest/SmartObject/CoverQuery/SO_CoverQuery。
  2. 选择需要配置的插槽，在插槽详情中找到 Runtime Tags（运行时标签）。请编辑这一项，而不是 Activity Tags。
  3. 在 HMS.Cover 下选择下面一种标签。不要同时选择多种姿态标签。
  4. 保存智能对象定义，重新开始 PIE 测试。已经运行的插槽不会自动重建初始标签。
Runtime Tag蓝图枚举结果
HMS.Cover.RightStanding右侧站立
HMS.Cover.RightCrouched右侧蹲伏
HMS.Cover.LeftStanding左侧站立
HMS.Cover.LeftCrouched左侧蹲伏

椅子测试目前设置为：BenchSlot1 → 右侧站立（启用）；BenchSlot2 → 暂时禁用，待对应方向动画接入。这是显式的测试配置，没有自动检测墙体边缘。左右应按你制作掩体动画时的角色参考方向理解，不能按摄像机屏幕的左右判断。

没有配置上述标签的普通智能对象会保持“未进入掩体”。若错误地配置了多个标签，当前蓝图按表中顺序取第一个匹配项；它不会表示多个方向同时可用。运行时改变标签后，可调用动画实例上的 RefreshCoverState 立即重新读取；当前通知不监听单独的标签编辑。

03 / NOTIFICATIONS

进入和离开时如何更新

接近目标Approaching：仍为未进入掩体。
播放进入动作Interacting：继续由状态树、动画查询和蒙太奇驱动。
完成贴靠Holding：通过位置与朝向校验后，读取插槽标签并设置 CoverState。
离开或取消恢复未进入掩体，并释放交互占用。

实际接线为：OnInteractionStateChanged → HandleCoverInteractionStateChanged → RefreshCoverState → Set CoverState。没有靠动画通知里的固定时间直接认定进入成功，因此进入途中取消、动画播放失败或目标失效都不会留下错误的掩体状态。

ABP_Famale 中的函数用途
FindCoverInteraction先查角色上的 HMS 交互组件；没有时再查 Controller，支持组件放在 AI 控制器上的情况。
BindCoverInteraction解绑本实例的旧回调，绑定新组件，并立即同步一次。不会移除其他蓝图的监听。
HandleCoverInteractionStateChanged接收原有交互组件的状态变化通知。
RefreshCoverState读取当前生命周期和插槽标签，决定 CoverState。

初始化动画和开始游戏时都会建立绑定。Update Animation 只检查所属交互组件是否改变，改变时才重新绑定；不会每帧把你的 CoverState 手动修改覆盖掉。组件结束生命周期时也会发出 Idle 通知清空状态。

C++ 新增的 GetClaimedSlotTags 只返回当前占用插槽的运行时标签；未占用、已释放或插槽失效时返回空集合。C++ 中没有新增掩体姿态枚举或 CoverState 成员。

04 / ANIMATION GRAPH

InCover → Chooser → 掩体待机

保持占用和播放待机分别由交互组件、动画蓝图负责。贴靠后不再一直暂停进入蒙太奇：状态机选中掩体待机后，进入蒙太奇用 0.35 秒混出，让待机继续循环。

  1. 打开 ABP_Famale → AnimGraph → New State Machine，找到 InCover。入口别名 Enter InCover 包含普通地面待机和移动状态；条件为 IsInCover。
  2. InCover 的 State Entry Function 为 OnStateEntry_InCover。它调用 SelectCoverIdle，执行 SetBlendStackAnimFromChooser，将状态设为 SM.State.Cover。
  3. 打开 /Game/MVTest/Famale/CT_Famale，进入当前武器对应的子表，找到 SM.State.Cover 行。该行继续查询独立资产 /Game/MVTest/Famale/CT_Famale_Cover。
  4. CT_Famale_Cover 先选择持枪贴靠或探出待机；未匹配时进入 CT_Famale_Cover_Concealed，由 CoverState 枚举过滤原有待机动画。原有“右侧站立”使用 MF_右侧站立掩体待机，已开启 Loop；其余三行保留为空，等待补动画。
  5. 离开时 CoverState 恢复“未进入掩体”。有移动输入则从 InCover 直接进入 Locomotion Transition；没有移动输入则进入 Idle Loop。可见姿势混合由现有 Blend Stack 执行。

状态图中的这三条新转换线采用零逻辑混合时间，避免两个状态同时更新并争抢 Chooser。画面仍有姿势混合：进入到待机由蒙太奇混出控制，待机变化及退出移动由 Chooser 的 BlendTime 控制。

混合时间在哪里调整

位置字段当前值 / 用途
DA_CoverQuery → Entry Transition移动进入混合时长0.4 秒：移动 → 进入动作。
DA_CoverQuery → Interaction Hold待机动画状态SM.State.Cover：与 InCover 查询时设置的标签相同。
DA_CoverQuery → Interaction Hold进入到待机混合时长0.35 秒：进入动作 → 循环待机。
DA_CoverQuery → Interaction Hold待机接管超时2 秒：动画配置无效时结束交互，避免角色永远冻结。
CT_Famale_Cover → Output StructBlendTime / Tags0.3 秒 / Interaction。Interaction 使贴靠待机继续清除移动遗留的根偏移。

DefaultSlot 必须勾选 Always Update Source Pose。进入蒙太奇满权重时，下面的状态机也需要更新，才能准备好待机后再交接。不要再额外添加盖在 DefaultSlot 后面的枚举姿势混合节点，否则会形成两套姿势选择。

后续增加其他姿态

  1. 准备与角色骨架匹配的原地循环动画，并开启动画资产的 Loop。检查首尾接续和根位置，避免待机漂移。
  2. 在 CT_Famale_Cover_Concealed 对应枚举行填入普通掩体动画；持枪探出配置见第 12 章，保留输出中的 Interaction 标签。
  3. 在智能对象插槽上配置相应的 HMS.Cover Runtime Tag，再测试进入和退出。

同一掩体内修改 CoverState 后，OnUpdate_InCover 比较 SelectedCoverState，仅在姿态变化时重新查询。当前版本尚未实现探头射击、掩体内横移以及左右/蹲立过渡动画；枚举表示所选姿态，不会自动生成缺失动作。

通用插件没有硬编码测试动画路径，也没有在 C++ 基类加入掩体枚举。其他智能对象可使用自己的蓝图枚举、状态标签和待机 Chooser。未配置待机动画状态的旧对象保留原有定格保持模式；本测试掩体已使用新的状态机待机流程。

05 / VERIFIED

如何检查是否接通

  1. 打开测试地图 L_MVThirdPersonTest，点击运行和“进入掩体测试”。
  2. 打开 ABP_Famale，在“调试筛选器”中选择运行中的测试角色。
  3. 观察 CoverState：移动和进入过程中为“未进入掩体”；贴靠完成后变为当前插槽配置。
  4. 再次点击按钮或按移动键离开，确认立即恢复“未进入掩体”。

本章原始待机验证以右侧站立为范围，当时两个测试插槽均使用右侧站立标签。第 12 章接入转身探出后，仅保留右侧边缘的 BenchSlot1 启用，BenchSlot2 暂时禁用。以下为原始待机验证记录。PIE 中验证了进入交接、连续两个待机循环、键盘直接退出到起步、按钮退出到普通待机、重复进入和进入途中取消。最终复测记录 1078 帧；稳定待机期间根位置无漂移，根部到插槽的平面误差约 0.03 cm；约 0.38 秒完成进入到待机混合，按键后约 0.03 秒进入移动转换状态。这些时间为本测试帧率下的观测值。出生点和编辑器性能设置已恢复。

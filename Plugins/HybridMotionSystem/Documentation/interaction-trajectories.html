轨迹曲线怎么读

用五条曲线检查根位移、根旋转和到接触时刻的剩余路程。

版本说明：本页旧截图中的 M_Cover 时间参数仅为历史示例；当前三方向资产、通知同步与测试方式请见第 07 章。

本页内容：轨迹曲线记录了什么

生成后看哪里

第一处：动画编辑器下方“通知”里出现 HMS_Interaction。

第二处：“曲线”分组显示五条 HMS_Interaction_ 开头的曲线。

第三处：时间轴上可以看到 PoseSearchBlockTransition 与 MotionWarping 窗口。曲线列表只能证明数据存在，还要检查时间范围和曲线值。

06 / TRAJECTORY REFERENCE

轨迹曲线记录了什么

曲线来自现有根骨。它们能帮助看清动画的运动方式，但不会给没有位移的动画凭空补出一条运动路线。

曲线名数值含义阅读方法
HMS_Interaction_RootX相对首帧根骨坐标系的 X 位移，cm。三条曲线共同构成原始根轨迹。它们不是世界坐标，也不是运行时变形后的实际路线；哪条轴表示前进取决于动画的根骨坐标系。
HMS_Interaction_RootY相对首帧根骨坐标系的 Y 位移，cm。
HMS_Interaction_RootZ相对首帧根骨坐标系的 Z 位移，cm。
HMS_Interaction_RootYaw从首帧开始累计展开的根骨 Yaw，度。用来观察根骨是否转向，以及转向过程。值为 0 不代表骨盆、胸部或整个身体姿态没有转动。
HMS_Interaction_DistanceRemaining沿根轨迹到接触时刻的剩余路程，cm；接触后为 0。这是动画里的路程，不是角色到场景掩体的直线距离，也不是导航路径长度。修改接触时刻后，应重新烘焙。

M_Cover 的实际例子

当前根骨主要沿局部 Y 轴移动，累计约 812.5 cm，明显位移到约 2.167 秒结束，根骨 Yaw 变化约为 0°。这不自动说明替代骨架有问题。

参考曲线与查询轨迹

这些曲线不会自动加入 Pose Search 特征。数据库仍需正确的 Schema、采样配置与角色 Pose History；运动查询的预测轨迹也需要运行时提供。

行为 → 装备 → 动作

角色的身体姿态、行为和装备是三个独立条件。先用行为与装备找到动作表，再在动作表里根据站立／蹲伏、移动状态、步态和方向选动作。智能对象的进入动画也读取同一组变量。

三个条件查询表层级蓝图控制智能对象进入添加动作测试与排查
01 / INPUTS

身体姿态、行为和装备各自表示什么

分类蓝图变量当前标签
身体姿态 StanceStance / GameplayTagContainerSM.Stance.Stand 站立、SM.Stance.Crouch 蹲伏、SM.Stance.Prone 匍匐预留。
行为状态 Behavior StateBehaviorState / GameplayTagHMS.Behavior.Relaxed 放松、Alert 警戒、Combat 战斗、Stealth 潜行。
装备武器类型 Equipped Weapon TypeEquippedWeaponType / GameplayTagHMS.Weapon.None 无武器、Pistol 手枪、Rifle 步枪。

BehaviorState 和 EquippedWeaponType 是 ABP_Famale 自己的蓝图变量，没有增加对应的 C++ 基类状态。原 WeaponPose 已重命名为 EquippedWeaponType，并迁移图中的连线与表格绑定。Stance 沿用原 HMS 动画输入；身体姿态一次只设置一个叶标签。

准备持枪与抬枪瞄准继续由原 RotationMode / Aim 控制。切换 Combat 不会自动改变武器、蹲伏或瞄准，切换 Stealth 也不会自动蹲下。游戏逻辑可按需要组合这些条件。

素材范围：当前站立／蹲伏运动与步枪动作保留；不同的行为分支暂用现有动作，可独立替换。手枪分支明确暂用通用无武器动作。匍匐只预留查询标签，没有增加匍匐动画、胶囊与 Mover 移动实现。

资源整理（2026.09.19）：角色资源已归入 /Game/HMS_Character/成年女性/人物；原 Female_Anim 资源按名称归入 /Game/HMS_Character/成年女性/动画/行为状态/{战斗、放松、通用}/空手，保留 Walk、Run、Crouch 等动作子目录。Neutral 对应战斗，Relaxed 对应放松；通用只是共享资源目录，不增加运行时行为标签。空手及手枪占位动作表已恢复原始步行动画，坡道混合空间和姿态查询同步恢复；旧模特步行文件保留但不再被这些动作表使用。这里的目录分类不修改已有 Chooser 的筛选条件。

02 / TABLES

普通动画的三级查询

CT_Famale                         ← BehaviorState
 ├─ CT_Relaxed_Weapons            ← EquippedWeaponType
 │   ├─ CT_Relaxed_None_Actions   ← 现有动作表，内部筛选 Stance 等
 │   ├─ CT_Relaxed_Pistol_Actions
 │   └─ CT_Relaxed_Rifle_Actions
 ├─ CT_Alert_Weapons
 ├─ CT_Combat_Weapons
 └─ CT_Stealth_Weapons

入口保持为 /Game/MVTest/Famale/CT_Famale。子资产在 /Game/MVTest/Famale/Queries/行为名 下。例如修改战斗步枪的移动动画，打开 Queries/Combat/CT_Combat_Rifle_Actions，再进入其 Locomotion Loops 或 Transitions 子表。

每个组合有独立的 Actions 和 Cover 表。修改一张动作表的筛选或引用，不会改变另一行为的表格；底层动画资产仍可共享，直接编辑共享动画文件会影响所有引用它的分支。各自的 Cover 表负责贴靠／探出待机，保留 InCover 和 SM.State.Cover。

行为标签为空或没有配置行时，回退到 Relaxed 的武器表；武器为空或没有配置行时，回退到同一行为的 None 动作表。两级使用 TagName 精确匹配：新增 HMS.Weapon.Rifle.Sniper 这样的子标签时，也需要增加明确的表格行。

03 / BLUEPRINT

从角色或装备系统修改条件

  1. 角色 Mesh → Get Anim Instance，取得正在运行的动画实例。
  2. 调用 Set Animation Query Context，同时传入 Behavior State 与 Equipped Weapon Type。此接口在游戏线程原子修改两个蓝图变量，返回 false 时两个值均不改变。
  3. 只改行为可调用 Set Animation Behavior State；只换武器可调用 Set Equipped Weapon Type。也可在动画蓝图里直接 Set 对应变量。
  4. 用 Getter 或实时 Chooser 调试确认输入。复制这套系统到其他动画蓝图时，保留这两个变量的名称、GameplayTag 类型和默认值。

普通循环、掩体待机或待机小动作期间，改变任意条件会触发重新查询，并给动作家族切换至少 0.3 秒混合。正在进行的起步、停步等非循环移动动作保留当前脚步，交接时使用新分支，避免修改条件时把动作反复从头播放。

原 Set/Get Animation Weapon Pose 默认接口仍兼容：优先读写 EquippedWeaponType，旧蓝图只有 WeaponPose 时继续支持旧变量。新接入应使用本章接口；不要在同一蓝图保留两套武器状态源。编辑器的 Install Animation Query Variables 可迁移变量，Rename Query Tag Binding 可迁移表格绑定。它们支持撤销，不自动保存。

04 / SMART OBJECT

掩体进入仍由智能对象与状态树控制

智能对象插槽 → 状态树进入任务 → DA_CoverQuery
 → CHT_Entry                         ← BehaviorState
 → CHT_Entry_Combat_Weapons           ← EquippedWeaponType
 → CHT_Entry_Combat_Rifle             ← Stance / 数据库
 → Pose Search → 蒙太奇及接入时间 → Mover + Motion Warping
 → InCover → 对应组合的 Cover 待机表

入口仍是 /Game/MVTest/SmartObject/CoverThreeWay/CHT_Entry，Profile 与状态树的引用保持不变。子表位于同目录的 Queries 下。查询上下文是角色当前 AnimInstance，因此普通运动和进入掩体读到的是同一组行为与装备变量。

目前各组合共用现有三个方向的进入数据库，表格已独立，可以替换为不同持枪或行为动作的数据库。接近目标期间持续查询当前条件；一旦开始播放进入蒙太奇，该次动作保持到交接，不因途中切换条件而从头重播。进入后的待机会使用最新条件。

只有站立进入素材，所以当前数据库行要求 SM.Stance.Stand。蹲伏或匍匐会明确报告缺少进入数据库，不会强行使用站立动作。近距离强制进入只在当前筛选出的数据库中寻找片段，不能绕过行为、装备或身体姿态筛选。

05 / EXTEND

给一个组合换上自己的动作

  1. 选定行为和装备组合，例如 Combat / Rifle。先备份对应 Actions、Cover 或进入数据库。
  2. 普通运动在该组合的 Actions 子表替换动画或混合空间，保留 State、Stance、Gait、方向等筛选及输出。需要姿态查询的行也应更新对应 Pose Search 采样。
  3. 交互进入先制作对应动画、生成进入通知和轨迹、创建蒙太奇与 Pose Search 数据库，再把数据库填到对应 CHT_Entry_行为_装备 中。新增蹲伏行时设为 Crouch，并配置实际蹲伏进入和待机素材。
  4. 新增一种装备时，在需要支持的四张 Weapons 表增加该装备标签行；智能对象进入的四张 Weapons 表也增加对应行。创建独立子表或明确复用现有表。
  5. 运行测试：待机时换行为、移动中换装备、起停中切换、靠近掩体时切换、掩体待机时换装备，并检查返回结果与混合。

编辑器蓝图／Python 可调用 Configure Animation Tag Router 来创建分流。它检查重复标签、上下文签名、无效属性和循环引用；会替换目标表的内容，因此先复制原动作表，再把入口改为分流表。未配置的 Fallback 可以留空，表示不支持该路线。

06 / DEBUG

测试面板与路线诊断

在 L_MVThirdPersonTest 中，点击行为按钮依次切换放松／警戒／战斗／潜行；点击装备按钮依次切换无武器／手枪／步枪。V 保留快速装备／收起步枪，B 保留抬枪或掩体探出操作。

编辑器接口 Trace Animation Query Route 输入 CT_Famale 或 CHT_Entry，以及角色 AnimInstance，可返回实际命中的三张表。它使用当前 Chooser 名称列过滤，不修改资产；返回空路径表示绑定或路线无效。该诊断只追踪前两级分流，最终选中的动画仍在叶表与 Pose Search 中检查。

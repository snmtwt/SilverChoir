09 — CHARACTER TESTING

运动、转身与布娃娃测试

先在测试地图确认基本动作，再把配置移到自己的角色。这里说明当前 CC5 测试角色的设置，以及如何记录一次不自然的动画切换。

本页内容：开始测试混合空间导航停步反向起步与记录布娃娃
01 / TEST SCENE

打开测试地图

  1. 打开地图并运行

    在内容浏览器中打开 /Game/MVTest/Maps/L_MVThirdPersonTest，点击播放。当前测试角色为 BP_MVThirdPersonTestPawn，动画蓝图为 /Game/MVTest/Famale/ABP_Famale。

  2. 测试走路、跑步与冲刺

    使用左侧面板选择步态，再用 WASD 移动，或右键点击地面导航。先走直线，松键停下，再按相反方向；之后再测试连续快速切换方向。

02 / BLEND SPACE

循环移动的混合空间怎么控制

当前样例的 BS_Slope 混合空间使用坡度作为 X 输入。平地附近使用 0，坡度超过死区后逐渐向正负 1 混合。它的坐标含义不是移动速度或左右方向。

  1. 打开动画蓝图的类默认值

    打开 ABP_Famale，点击“类默认值”，在详情中搜索 Blend Space 或展开 HMS → BlendSpace。

  2. 选择自动坡度或自定义输入

    默认关闭 Override Blend Space Inputs，使用自动坡度。接入自己定义坐标轴的混合空间时，启用该选项，并通过动画蓝图更新 Blend Space Input Override 的 X、Y 值。勾选后只填写一个常数，会保持在固定混合位置。

参数作用与当前默认值
Slope Blend Dead Zone15°。小幅地面倾斜保持中性输入。
Slope Blend Full Angle30°。达到该坡度时输入到达正负 1。
Get_BlendSpaceInputs输出已接到主 Blend Stack 的 Blend Parameters。新动画蓝图也需要完成这条连接。
03 / NAVIGATION BRAKING

让停步在仍有速度时开始

导航接近目标时逐渐减小移动输入，HMS 保留这个输入幅度并标记导航减速。动画状态机据此进入停步；Mover 同时降低实际速度。只把方向归一化后传给 Mover，会丢失导航给出的减速信息。

测试角色使用 HMS_NavMoverComponent，控制器使用 HMS_PathFollowingComponent。步态和蹲伏速度在发起导航前同步，导航途中改变步态或蹲伏状态也会刷新刹车距离。蹲伏不会再沿用站立跑步的速度估算刹车距离。复用到自己的角色时，需要同时保留这两部分接线。

配置如何理解
Requested Max Speed当前步态的目标速度，必须与输入生产器和 Mover 的速度设置一致。测试角色走路 / 跑步 / 冲刺分别为 165 / 375 / 585 厘米每秒。
Braking Deceleration用于估计停止距离，默认 1000，应与 Walking Mode 的 Stopping Deceleration 一致。
Braking Lead Time额外提前量，默认 0.05 秒。增大会更早开始减速；距离还会考虑导航角色半径。

近处走路，远处按所选步态移动

MVTest 控制器默认开启“短距离导航自动走路”，阈值为 300 厘米，比较的是投射到导航网格后的有效路径长度。200 厘米路径已验证使用走路，600 厘米路径保留所选跑步。蹲伏保持蹲伏速度；键盘接管后恢复手动选择的步态。面板“步态”显示角色实际使用的值。

配置位于 AMWTestPlayerController 的 HMS → Navigation 分类：bWalkForShortNavigation 和 NavigationWalkDistance。可在派生的控制器蓝图类默认值中调整。这项自动步态选择目前接入 MVTest 右键导航入口。

停步期间再次输入移动

停步状态收到新的世界空间移动输入时，优先返回移动状态，不等待停步播完或轨迹预测刷新。自动化回归覆盖停步开始 0.15 秒后同向恢复、反向恢复，以及停步较晚阶段重新起步。接入其他 Pawn 时也需要在每次输入生产时发布最新方向，包括松开时的零向量。

普通右键导航允许在到达半径内结束，不保证胶囊中心精确落在点击坐标。智能对象交互的最终插槽对齐由进入动画的根运动与对齐逻辑处理。

04 / START & TURN

检查“180° 起步只闪一下”

起步动画通过查询选择资产和起播时间，因此不一定从第 0 秒开始。当前代码在起步建立姿势的短暂窗口内抑制重复重选及过早完成判断，并避免把起步转身的轨迹误当成持续绕圈而自动降为走路。这个保护不会强制角色把整段起步动画播完。

本轮检查确认：跑步转身动画的主要根骨旋转集中在前约 0.65 秒。原先从 0.4 秒起播，再使用 0.3 秒混合，会把大部分转身隐藏在混合期间。现在根据动画实际根骨旋转量限制起播时间；当前 CC5 跑步转身样本从约 0.117 秒开始，使用 0.15 秒混合。90°、135° 与 180° 键盘起步回归均选择了 Reface Start 动画。45° 等小角度输入选中较大角度转身片段时，保留合适的中途匹配时间，同时缩短混合；直线起步继续使用原来的混合设置。总播放时长不能单独证明转身表现正确，还应检查前半秒的姿势与朝向。

  1. 开始记录

    在运行中的左侧面板点击“记录动画（30 秒）”。随后进行容易出现问题的操作，例如向前移动、松键停下、立刻按反方向。

  2. 出现问题后保存

    点击“停止并保存动画记录”，或等待 30 秒自动保存。退出本次运行也会保存已经记录的内容。

  3. 找到 CSV 文件

    打开项目目录下的 Saved/HMSReports，找到最新的 Locomotion_*.csv。记录包括键盘方向、速度、角色与根骨朝向、状态、选择与实际播放的动画、播放时间、混合参数和导航减速标记。反馈时附上 CSV，并说明大约第几秒出现问题及当时的操作。

记录默认关闭，仅在按钮开启后采集，不持续向 UE 输出逐帧日志。该按钮属于 MVTest 测试界面。

05 / CC5 RAGDOLL

为不同骨架配置布娃娃

不同骨架需要相匹配的物理身体、约束、胸部朝向轴与起身动画。只替换模型，继续使用另一套骨架的起身蒙太奇或物理配置，不能保证正确结果。

当前 CC5 配置位置 / 含义
Physics Asset Override/Game/MVTest/Famale/PA_CC5_HMS_Ragdoll_Constrained，配置在测试 Pawn 的 Mesh 上。原始模型物理资产保留。
Physics Control Asset/Game/MVTest/Famale/PCA_CC5_Female，使用 CC5 物理资产，保留样例的物理控制配置方式。
骨骼与朝向盆骨 pelvis、胸部 spine_04。默认从参考姿势推导胸部朝向轴，也可手工覆盖。
起身动画/Game/HMS_Character/成年女性/动画/行为状态/通用/空手/Ragdoll 中的 AM_M_ragdoll_getup_stand_B 和 AM_M_ragdoll_getup_stand_F。查询结果骨架不兼容时使用已配置的兼容后备动画。
恢复配置默认物理控制配置为 Kinematic，进入布娃娃时使用 Ragdoll。

倒地后一直滑动，先检查附属模型

本次测试发现头发模型的物理碰撞会持续推挤它所跟随的身体。动画数据组件新增“布娃娃时禁用附属模型物理碰撞”，默认启用：进入布娃娃时暂停非独立模拟的附属模型物理碰撞，保留查询；起身时恢复原设置。

从倒地位置连续起身

物理模拟结束时保存倒地姿态，将快照转换到恢复后的 Mesh 坐标系，并把根骨补偿传给直接子骨骼。Offset Root Bone 的 Reset Every Frame 已连接 ShouldResetOffsetRoot：倒地与起身期间重置偏移，防止把移动时累积的变换再次套到快照上。

本角色还有站立用的脚部旋转和盆骨 8 厘米修正。这五个 Transform Bone 节点的 Alpha 已连接 Get_RetargetCorrectionAlpha；倒地和起身时为 0，恢复站立后在 0.25 秒内回到 1。原有修正值保留。换用其他动画蓝图时应检查同样的重复修正问题，不要直接删除站立所需的骨骼调整。

两种受力方向的仰面起身回归中，首帧水平位置保持在倒地位置附近；约 2.15 厘米的高度变化来自 Mover 恢复地面接触。起身动画自身后续的身体移动仍会正常播放。

根运动和起身结束时机

起身蒙太奇现在通过 Mover 播放，动画里的根位移会带动角色胶囊一起移动；不会只移动骨架后又回到原胶囊。起身完成与中断使用实际播放回调，不再用固定秒数的计时器。加速播放、提前中断或起身途中再次倒地，都能按当前状态结束或重新进入物理模拟。测试面板会显示“起身中”。

起身末尾闪回倒地姿势

动画蓝图的 DefaultSlot 应开启 Always Update Source Pose。同时检查 Ragdoll 状态机：从 Blend Out Pose（倒地快照）回到 NoRagdoll 的过渡，需要关闭 Only Evaluate When Active。UE 会在蒙太奇覆盖时把底层图标记为非活动；若此规则仍受限制，快照状态会等到起身蒙太奇混出时才恢复，造成已经站起的身体突然下沉。只调整这条恢复规则，不应批量解除普通移动状态机的活动限制。当前 ABP_Famale 已完成此配置；起身锁定仍由原播放完成／中断回调解除。

换角色后仍需手工检查

在 Physics Asset 编辑器里检查胶囊是否包住躯干、四肢是否连接到正确父身体，以及关节角度是否适合动作。当前生成工具面向已约定骨名的 17 个身体，不会自动理解任意命名的骨架。测试时分别检查仰面、俯面、侧倒及起身；已补测仰面与俯面起身、起身中断、播放加速以及起身中再次倒地。复杂斜坡和联网同步仍需单独测试。

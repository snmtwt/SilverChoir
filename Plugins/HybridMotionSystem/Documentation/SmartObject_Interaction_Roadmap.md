# 智能对象交互：连续接入方案与动画工具

## 历史方案（以下为连续接入实现前的分析）

本轮完成现有状态树和 C++ 任务检查，以及动画编辑器的「HMS工具 → 创建进入通知与轨迹…」。按钮测试目前仍执行上一版固定进入流程；本轮没有将其替换为新的状态树流程，也没有宣称消除运行时停顿。下述运行时改造是接下来的实施方案。

## 当前停顿的来源

上一版 `FindAndUseSmartObjectWithProfile` 执行 `Approaching → Aligning → Interacting`：到达固定入口后停止导航，等待速度低于 1 cm/s、朝向误差小于 0.1°，随后从配置中的固定秒数播放 Montage。它只验证了根运动播放与最终落点，绕过了物体的 Gameplay Interaction StateTree，也没有使用 Chooser / Pose Search 的 StartTime。

当前 `ST_HMS_SmartObject_Bench` 的 `Move To Slot And Play Entry` 已有四个并行任务：原生 MoveTo、HMS Focus To Target、HMS Ignore Collision、HMS Evaluate and Play Motion Matched Montage。最后一个任务通过 `CHPT_座椅代理表` 查询动画，并负责状态完成。这是后续复用的起点，不需要从零复制一套掩体状态机。

现有 `HMS_PlayAnimFromBestCostTask` 还需在迁移时处理以下问题：

| 当前实现 | 影响 | 改造方向 |
|---|---|---|
| AI 路径使用 `CurrentPath->GetLength()` | 取的是路径总长，不是角色当前位置之后的剩余距离，可能过晚开始查询 | 使用活动路径段和当前位置计算剩余长度；玩家和 AI 共用接口 |
| 接近角使用角色前向与目标方向夹角 | 无法稳定区分相对物体的前、后、左、右 | 查询上下文同时提供槽位局部接近角、速度方向角、根朝向差 |
| `Destination` 同时供距离判断和 Warp Target 使用 | 混淆可走到的入口与身体最终接触位置 | 分成导航入口区域、接触目标、动画接触参考变换 |
| 只保留历史最低 Cost 的动画和 StartTime | 当前姿态和目标已变化，旧结果仍可能被采纳 | 使用当前帧有效候选，必要时短时稳定处理，并在交接时重新验证 |
| 原生 StateTree MoveTo 输入是 `AAIController` | 当前测试玩家是 PlayerController，不能直接替换按钮就认为通用 | HMS 导航任务通过 Pawn/NavMover/PathFollowing 适配两类控制器 |
| Montage 不再播放就判成功 | 被打断也可能被当作成功 | 区分完成、混出、打断和取消，统一槽位与根运动清理 |

该 StateTree 的 Loop / Exit / ReleaseSlot 状态在当前读取的编辑数据中没有任务。进入测试可先在 Entry 后完成并释放；持续交互阶段要明确填入实际任务，不能仅根据状态名称假定已有行为。

## 应有的连续接入流程

1. 请求交互，查找并占用合法槽位，由槽位 Behavior 启动交互 StateTree。
2. 接近状态同时执行导航与动画查询。此时保留正常 Mover 运动、Pose History 和预测轨迹；不先停住，也不强制面向最终接触朝向。
3. Chooser 按角色、交互类型、速度、姿态和物体局部接近方向筛选候选动画；Pose Search 在允许接入范围内返回姿态 Cost 与 StartTime。单一 M_Cover 也可做姿态时间匹配，不必先补齐多方向素材。
4. 除姿态评分外，检查候选从 StartTime 到接触帧的剩余根位移、旋转、障碍与当前目标的可达性。与目标位置明显不相容的低 Cost 姿态不能直接播放。
5. 候选可行时，同一帧提交接触目标与查询得到的 StartTime，并把控制权从导航交给 Mover 根运动；终止导航请求时保持当前速度，不加入“等待速度归零”的状态。合理的混合时间和姿态匹配共同完成衔接。
6. 用根运动窗口对齐到接触目标；动画完成后按交互配置进入保持或退出。取消、失败、物体失效统一恢复碰撞、输入并释放槽位。

「动画可接入范围」是一段时间，不是固定世界坐标。某一候选帧到接触帧的相对根运动，可以反推出与该帧对应的世界接入姿态；不同候选帧形成一片可接入区域。导航需要把角色带入可行区域，不能先走到唯一动画首帧位置再切动画。

只有一个动作时，可以让各方向来的角色在正常移动中绕入适合这段动作的接近方向；不宜依靠大角度 Motion Warping 把同一个动作强扭成任意方向转身。若需要从任意角度直接贴入，后续再补左右进入、急转进入或经过验证的镜像动画。

## M_Cover 与通知、轨迹

现路径为 `/Game/HMS_Character/成年女性/动画/行为状态/通用/空手/Cover/M_Cover`。当前片段约 3.233 秒，根骨累计移动约 812.5 cm，明显位移到约 2.167 秒结束，根骨没有明显 Yaw 转动。身体转身仍可能出现在骨盆与上身骨骼，这不等于骨架有错误，也不需要因此修改替代骨架。

需要确认三个时间：允许查询切入的开始、允许查询切入的结束、希望对齐到物体的接触时刻。开始应放在转身前仍具有可匹配步态的位置，结束应放在已明显转入接触姿态之前，保留足够的动作供查询匹配。根位移停止时刻只能作为接触时刻的初始建议。

工具使用方法：

1. 打开源动画序列，点「HMS工具 → 创建进入通知与轨迹…」。Montage 请先打开其源序列；本版工具不处理复杂 Montage 分段时间映射。
2. 查看根运动分析，调整接入开始、结束和接触秒数。默认根据最后明显根运动给出范围，并不自动识别转身语义；已有工具标记会被读回。
3. `WarpTargetName` 默认 `SmartObject`，与现有状态树任务一致。
4. 点击「一键生成 / 更新通知与轨迹」，检查时间轴，满意后保存。支持 Ctrl+Z。原有权重曲线与转身曲线工具仍在菜单中。

生成内容：

| 数据 | 作用 |
|---|---|
| `HMS_Interaction` 轨道中的 `HMS.EntryWarp` | 原生 Motion Warping Notify State，配置 Skew Warp、平移与旋转对齐，忽略 Z；范围从接入开始到接触时刻 |
| `HMS.BlockBeforeEntry` / `HMS.BlockAfterEntry` | 原生 Pose Search Block Transition In，禁止选取范围外的新起播点，但允许已进入的动画继续播放尾段 |
| `HMS_Interaction_RootX/Y/Z` | 相对动画首帧根骨坐标系的实际根轨迹，cm |
| `HMS_Interaction_RootYaw` | 根骨累计展开 Yaw，度；不会从骨盆转动伪造根旋转 |
| `HMS_Interaction_DistanceRemaining` | 从当前时间沿根轨迹到接触帧的剩余路程，接触后为 0 |

工具只更新自己生成的通知及所选的五条曲线；其他通知会保留。已有重叠的非工具 Motion Warping 窗口会阻止生成，避免双重变形。若没有有效根位移，工具会提示先修复动画根轨迹。没有开启“生成参考曲线”时，已有参考曲线也会保留，需注意它们可能与新时间范围不同。

这些曲线是检查和后续工具读取的数据，不会自动变成 Pose Search 特征。Pose Search 数据库的 Schema、轨迹通道、Pose History 与查询上下文仍需配置；编辑通知后应重建相关数据库索引。若已有 Sampling Range、Exclude 或其他 Block 通知，还应检查它们与新接入范围的交集。

Motion Warping Notify 也不会单独解决停顿：状态树必须真正执行查询并提交同名 Warp Target，角色的 MotionWarping 组件必须启用 `bSearchForWindowsInAnimsWithinMontages`，才能扫描 Montage 内源序列上的窗口。上一版固定进入自带另一套 Modifier，不能同时叠加新的窗口；正式接入时将用统一的窗口执行路径替换它，并重新验证侧向误差和移动交接。

## 插件结构与后续工具

建议保留一套生命周期组件和 StateTree 模板，交互配置资产保存进入查询表、可选保持/退出、接触目标定义、碰撞策略及中断策略。角色通过适配接口提供 Mesh、Mover、Pose History 和导航能力；物体只提供 Definition、槽位、入口区域和接触变换。运行模块不引用 `/Game` 示例路径。

按下面顺序实施，每步都可以单独验证：

1. **单动作连续进入**：完善查询任务和玩家导航适配，把 UI 请求接到槽位 StateTree，替换固定起点与停住对齐流程。验收移动中切入、StartTime 位于允许区间、目标对齐、取消重试，记录关键交接速度与中断结果。
2. **配置与模板**：把椅子、掩体差异放进交互资产，提供 Entry / Hold / Exit 模板和显式代理资产选择；避免自动取代理表第一个条目。
3. **制作向导**：选择角色与动画，创建 Montage、Chooser、Pose Search 数据库、Smart Object Definition、StateTree 模板引用并统一命名；可重复运行、有修改预览。
4. **场景调试工具**：显示槽位接触姿态、导航入口区域、原始与变形后的根轨迹、所选帧和评分；提供四周接近与取消重试测试按钮。优先用可关闭的可视化，避免常驻日志。
5. **更多场景**：多方向动作、移动物体、持续掩体、网络与异步 Mover，分别添加约束和测试，不把当前同步单机测试当作这些能力已经完成。

## 需要用户参与的部分

- 确认 M_Cover 想保留的转身前接入片段和贴靠帧；可以给帧号或秒数，也可先用工具建议范围试验。
- 确认最终接触关系：是背部贴靠、侧身贴靠，最终朝向怎样；椅子只是几何占位物，不能从椅子座位自动推断掩体表面。
- 在接入链路完成后判断动作观感，尤其是足步、身体接触和可接受的绕行幅度。只有在单动作覆盖不了目标方向时才需要补动画。

09 / TROUBLESHOOTING

常见问题

提示“时间必须满足……”

检查三个值是否严格递增，且接触时刻不超过动画长度。例如 S=1.567、E=0、C=2.167 无效。应先把 E 调整到 S 与 C 之间。0 不表示自动计算。

提示已有其他 Motion Warping 窗口

在通知时间轴查看重叠范围。确定哪个窗口才是这次交互要用的，调整或移除不需要的旧窗口后再生成。不要把两个窗口叠加当成覆盖。当前工具只自动替换能识别的 HMS 通知。

生成后仍然先停一下再播放

当前测试按钮已采用移动中查询。若仍先停住，请检查槽位是否引用 ST_CoverQuery，任务是否为 HMS Approach and Enter (Pose Search)。旧的固定进入接口仍会等待停住对齐。若提示查询范围错误，请在 HMS 工具中更新进入数据库的范围与索引。

动画播放了，但没有贴到物体上

依次检查根运动开关、MotionWarping 组件、目标名称、窗口扫描和运行时提交的目标位置。还要检查碰撞是否阻挡，以及所选起播点到目标之间是否需要过大的变形。

RootYaw 是 0，但人物明明在转身

该曲线只记录根骨 Yaw。身体转动可能主要由骨盆、脊柱和四肢姿态完成。请在动画编辑器分别查看根骨和身体姿态，不能仅据这一条曲线判断骨架错误。

为什么不直接把前面的跑步动画删掉

限制查询范围可以保留原动画和动作上下文，允许在转身前选择更匹配的步态。裁剪也是制作选择，但会改变时间基准，需要同步重做 Montage 分段、通知和数据库索引。

只用一段动画，能从任何角度自然进入吗

可以先让不同方向来的角色在正常移动中绕入适合该动作的方向。若需要从任意方向直接进入，通常还要补充方向变体或合适的转向动作，过强的对齐无法替代素材。

工具能一键判断转身帧和贴靠帧吗

当前只能根据根位移和根旋转估算初始范围。身体接触物体的含义需要人看姿态确认。它不会自动添加脚步声、脚底锁定、碰撞事件或交互完成回调。

10 / CHECK & GLOSSARY

保存前做一次检查

  • 接入范围覆盖转身前可匹配的步态，并保留足够的进入动作。
  • 接触时刻符合想要的身体接触姿态，时间顺序有效。
  • 通知轨道中的对齐窗口没有意外重复或重叠。
  • 修改接触时刻后，已更新需要的参考曲线。
  • 成功生成后已保存动画，必要时重建查询数据库索引。
  • 进入测试验证了起播、落点、取消与再次交互，而不只是在编辑器预览里看起来正常。

术语速查

Smart Object
场景中可以交互的对象定义与运行时实例；槽位提供交互位置和使用行为。
StateTree
组织寻找、接近、进入、保持、退出等阶段的行为流程。
Chooser
根据输入条件筛选动画等结果的规则表。
Pose Search
通过角色姿态等特征查询候选动画，寻找适合的动作和时间点。
Montage
可控制起播时间、混合和分段的动画播放资产。
Root Motion
从动画根骨提取、用于驱动角色的位移与旋转。
Warp Target
运行时提供给 Motion Warping 的目标位置与朝向。
Notify State
覆盖一段动画时间的通知状态。不同类型由不同系统解释其含义。

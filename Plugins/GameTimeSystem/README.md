# GameTimeSystem 游戏时间系统

独立的游戏日历和一次性预约任务。默认日期 `2049-01-01 00:00:00`，流速 `1`，初始未暂停；可在 **项目设置 → Plugins → 游戏时间系统** 修改。插件已在 SilverChoir 工程中启用。

## 结构与生命周期

| 类 | 职责 |
| --- | --- |
| `UGTS_TimeSubsystem` | GameInstance 子系统，创建管理器、驱动时钟、结束游戏时清理 |
| `UGTS_TimeManager` | 持有当前日期、流速、暂停状态和预约队列，派发通知 |
| `UGTS_TimeSettings` | 初始日期、初始倍率、暂停配置、管理类和每帧任务预算 |
| `UGTS_TimeLibrary` | 蓝图时间与任务算法节点，自动解析世界上下文 |
| `UGTS_TimeTask` | 可继承的时间回调对象，在蓝图中实现具体业务 |

每个 GameInstance 只有一个时钟，PIE 多实例相互独立。流式子地图和 OpenLevel 切换共用同一时钟；结束游戏时清除尚未执行的预约。任务可从自己的世界上下文访问函数库。

插件不改变 UE 的全局时间膨胀。流速使用**引擎未应用 World TimeDilation 的帧时间**，`60` 表示每秒帧时间推进游戏一分钟；不是操作系统墙钟，也不计算退出游戏期间的离线时间。引擎固定帧时间或最大 DeltaTime 设置仍会影响推进。

只有 Game/PIE 世界开始游戏后才自动推进；编辑器预览不推进。默认开启“随游戏暂停”：UE 的 Set Game Paused 会同时停止日历；“设置游戏时间暂停”仅暂停本插件的日历和任务派发，不暂停 UI、相机或其他系统。

## 设置、查询时间

- **设置游戏时间（年月日时分秒）**：输入年月日时分秒，返回是否成功。日期先校验，例如 `2049-02-29` 被拒绝，不改变原时间。
- **设置游戏时间**：接受 UE 的 DateTime。用于恢复已有日期或直接跳转到指定日期。
- **获取当前游戏时间**：返回 DateTime，可用 UE `Break Date Time` 拆分日期。
- **设置游戏时间流速**：非负倍率；负数、NaN 和无穷大被拒绝。
- **设置游戏时间暂停**：true 暂停、false 继续，保留原倍率。
- **获取游戏时间流速 / 游戏时间是否暂停**：读取状态。
- **获取游戏时间管理器**：可绑定 `游戏时间已改变`、`时间流速已改变`、`时间暂停状态已改变`。

自动推进时，“游戏时间已改变”每个跨越整秒的帧最多广播一次，不会在高倍速下一秒一秒补发。显式设置到不同日期时立即广播。需要精确预约请注册任务，不要依赖该显示刷新通知逐秒累计。

流速 `0` 冻结日历，但允许执行已到期的预约；需要同时停止回调时请使用暂停节点。暂停状态下仍可以手动设置日期或登记任务，任务等恢复后再派发。

## 文本控件自动显示时间

在 UMG 控件的 **Construct** 中调用 **注册游戏时间文本控件**，传入一个 `TextBlock` 和 `Text` 类型的日期时间格式。注册成功会立即显示当前游戏时间，之后自动跟随时钟更新，不需要在 Widget Tick 中设置文本。

```text
Event Construct
    → 注册游戏时间文本控件
        TextBlock = 顶部时间文本
        Format = {Year}年{Month}月{Day}日  {Hour}:{Minute}:{Second}

Event Destruct
    → 取消注册游戏时间文本控件（顶部时间文本）
```

| 占位符（区分大小写） | 示例 |
| --- | --- |
| `{Year}` | `2049`，至少四位 |
| `{Month}`、`{Day}` | `01`、`09`，两位补零 |
| `{Hour}`、`{Minute}`、`{Second}` | `08`、`05`、`03`，24 小时制、两位补零 |
| `{Weekday}` | `星期六`等，可本地化 |

格式示例：`{Year}-{Month}-{Day} {Hour}:{Minute}:{Second}`、`{Hour}:{Minute}`、`基地时间：{Month}/{Day} {Weekday}`。使用 UE 命名格式占位符，不使用 `yyyy-MM-dd` 或 `%Y-%m-%d` 语法；不要预先将格式中的时间替换成固定文本。

- 支持同时注册多个文本，各自使用不同格式。同一个控件再次注册会替换原格式并立即刷新。
- 自动时间推进时跟随整秒变化更新，手动设置日期时立即更新，包括时钟已经暂停时。暂停期间不会自行改变显示。
- 格式化结果与当前文本相同就不重复调用 SetText，避免只有分钟或日期的显示触发多余布局更新。
- 仅保存控件弱引用，不阻止 Widget 被垃圾回收；失效引用自动清理。移出屏幕但仍被业务持有的 Widget 不等同于销毁，建议在 Destruct 中明确取消注册，Construct 中重新注册。
- 取消注册保留最后显示的文本；还提供 **游戏时间文本控件是否已注册** 查询。
- **格式化当前游戏时间** 只生成一个 FText，不注册控件，适合日志或一次性提示。
- 注册期间由插件管理该控件的 Text 属性，使用 UTextBlock::SetText 会解除原有 Text 属性绑定；不要再由其他 Tick 或绑定同时写入。字体、颜色等样式仍在原 Widget 蓝图中设置。

## 蓝图回调任务示例

假设任务是在 `2049-01-02 08:30:00` 完成训练：

1. 新建蓝图类，父类搜索 **游戏时间回调任务 / GTS_TimeTask**，例如 `BP_TrainingTimeTask`。
2. 在任务蓝图增加自己的 `UnitID` 等参数，并重载事件 **时间回调任务**。事件提供 `ScheduledTime`（原预约时间）和 `CurrentTime`（本帧已推进到的时间），在这里实现训练完成逻辑。
3. 在业务蓝图调用 **创建游戏时间回调任务**，类选择 `BP_TrainingTimeTask`。返回值自动使用所选子类类型，先填写 `UnitID` 等参数。
4. 调用 **构造有效游戏日期**：Year=2049、Month=1、Day=2、Hour=8、Minute=30、Second=0。只有返回 true 时继续。
5. 将创建的对象和输出日期交给 **注册游戏时间回调任务**。保存返回的任务 ID；无效 GUID 表示注册失败。
6. 游戏时间达到或超过目标时，系统调用该对象的 **时间回调任务**，本次预约随即完成。

```text
创建游戏时间回调任务（BP_TrainingTimeTask）
    → 设置任务的 UnitID 等参数
    → 构造有效游戏日期（2049, 1, 2, 8, 30, 0）
    → 成功分支：注册游戏时间回调任务（任务对象，日期）
    → 保存返回的 TaskId
```

注册和设置日期都不会同步执行任务，最早在下一次未暂停的时钟更新中回调，方便先完成初始化或保存 TaskId。已经过去的时间也遵守这个规则。

**取消游戏时间回调任务** 接收 TaskId；成功取消后不会执行。另提供 **游戏时间任务是否已注册**、**获取待执行游戏时间任务数**。一个任务对象同时只允许一条预约，需要并行预约时分别创建对象。一次回调开始前旧登记已移除，可以在回调里再次注册自己，形成显式循环任务。

## 调度与资源规则

- 使用按预约时间和注册顺序排列的最小堆，无任务到期时不遍历整个任务列表；相同时间按注册顺序执行。
- 高倍速或手动向前跳时间不会漏掉被跨过的任务。每帧默认最多执行 128 个回调，超出的分后续帧执行，可在设置中调整。
- 回调内新注册的任务最早下一帧派发。若新任务时间已经过去，它按当前时刻排队，避免反复插队饿死原有到期任务；传入回调的 ScheduledTime 仍保留原预约日期。
- 回调可取消其他任务或暂停日历；暂停后停止本帧后续派发。回调执行期间拒绝再次设置日期，避免递归改变正在处理的时间范围。
- 向后设置日期不会恢复已经完成或取消的预约。若需要再次执行，应明确重新注册。
- 超出 DateTime 支持范围时截到 `9999-12-31` 的最后时刻；先按帧预算处理剩余任务，再自动暂停。
- 注册后管理器通过 UPROPERTY 强引用持有任务，不需要业务蓝图额外保活。创建但尚未注册的对象需要调用者保存引用；执行完成或取消后管理器释放引用，长期异步工作仍需自行持有对象。
- 所有操作在游戏线程执行。任务应避免同步执行过重工作；每帧预算限制的是回调数量，不是单个回调内部耗时。
- 本插件提供运行时日历与预约，不自动写存档或复制到网络。存档时由游戏记录当前时间、倍率、暂停状态和业务任务参数；读档后用这些节点恢复时间并重建预约，不序列化临时 UObject 指针或旧 TaskId。

## C++ 使用

使用插件 API 的游戏模块在 Build.cs 加入 `GameTimeSystem` 依赖，再包含 `GTS_TimeLibrary.h`、`GTS_TimeTask.h` 等头文件。蓝图调用不需要添加游戏模块依赖。

核心管理器还提供 `AdvanceTime(double)`，用于子系统推进和确定性测试。正常业务只需使用函数库，不要另行 Tick 管理器，否则会重复推进时间。

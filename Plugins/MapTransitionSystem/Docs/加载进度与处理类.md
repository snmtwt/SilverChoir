# 自动进度上限与子地图处理类（1.2）

## 整图切换

“按地图对象切换地图”“按地图与处理对象切换地图”增加末尾参数 **自动加载进度上限**。
完整切换请求中对应 `AutomaticProgressMax`。默认 `1.0`，现有节点保持自动完成；`0.8` 表示 80%，不是填写 80。

- 自动阶段按上限缩放：原 50% 阶段在上限 0.8 时反馈 40%；自动工作完成时最多到 80%。
- **设置切换进度**始终接受 0～1 的绝对进度，可超过自动上限。进度只增不减，非有限数值被忽略。
- “需要主动通知加载完成”为 false：地图切换成功后自动调用 `OnMapLoaded`，等待配置的延迟秒数后关闭加载界面。
- “需要主动通知加载完成”为 true：等待调用“通知地图加载完成”，随后调用 `OnMapLoaded`，等待配置的延迟秒数后关闭加载界面。重复通知不会重置延迟。
- 关闭界面与进度数值无关：进度不足 1 也会按时关闭，设置为 1 不会提前关闭。延迟为 0 时就绪处理完成后直接关闭。
- 地图处理对象在 `OnMapLoaded` 回调后释放，不随进度上限改变生命周期。
- “需要主动通知加载完成”仍控制何时调用 `OnMapLoaded`，与进度上限独立；设置进度不会代替“通知地图加载完成”。
- 关闭延迟不再把手动进度固定限制在 90%。请求失败仍按失败流程关闭界面，不会等待手动进度。

例：切图时设上限 `0.8`，启用主动通知 → 目标地图初始化时设置 `0.85 / 0.95` → 初始化完成调用“通知地图加载完成” → 延迟结束关闭界面。是否将进度设为 `1.0` 不影响关闭。

## 子地图

1. 创建 **子地图资源处理类**（`UMTS_SubMapHandler`）的蓝图子类。
2. 在发起加载前，从“获取子地图子系统”绑定 **子地图加载进度变化**。事件参数为 `MapID` 和 `FMTS_MapTransitionPayload`。
3. 调用 **按处理类加载子地图**，传入原有地图数据资产、位置、旋转、处理类和自动进度上限。
4. 处理类可实现：
   - **预加载子地图资源**：返回 bool；false 中止本次加载。此时实例 ID 已保留，可保存实例相关数据。
   - **子地图加载完成**：关卡已加载且可见时调用一次；可以通过 `Map.StreamingLevel` 定位该实例。
   - **子地图加载失败或取消**：预加载拒绝、创建失败、异步加载失败或未完成时卸载，调用一次。
5. 若上限为 `0.8`，完成自定义初始化时调用 **设置子地图加载进度**，传入对应 MapID 和绝对进度，最终设为 `1.0`。

每个实例拥有独立处理对象和进度，不共用整图切换的处理对象。处理对象的 `GetWorld()` 返回当前父世界。
子地图处理类与整图处理类采用相同的预加载/完成/失败模式，事件参数专用于子地图；原整图处理类蓝图不能直接作为子地图处理类。
“获取子地图资源处理对象”或函数库“根据ID获取子地图处理对象”可按 ID 查询对象。初始化完成后仍保留同一个对象；卸载请求发出后也保留，直到关卡实际移除。同步创建失败会立即移除，世界销毁时也会清理。

原 **加载子地图**节点仍有效，使用默认处理类与上限 1；也会反馈进度。
“获取所有子地图”结果新增 `LoadingPayload` 和 `AutomaticProgressMax`，可随时查询当前状态。

子地图 `State=Loaded` 只表示关卡已显示；自定义工作是否全部完成需看 `LoadingPayload.Phase=Completed`。
进度阶段为预加载 5%、开始流式加载 30%、等待可见 80%、应用资源 90%、自动工作完成 100%，再乘以上限。
阶段可能在同一帧完成，**这是加载阶段进度，不是磁盘读取字节的精确百分比**。子地图进度直接反馈，不使用整图进度平滑定时器。

旧的“加载子地图 / 按处理类加载子地图”不自动创建全屏加载 UI。可以按 MapID 筛选进度事件，将 Payload 交给自己的 UI；
使用 `UMTS_MapLoadingWidget` 时可调用 `ApplyTransitionPayload` 复用现有显示逻辑。
不同 ID 可以并发加载；卸载某个实例不会覆盖其他实例或整图切换的进度。

参数无效或 ID 重复时请求尚未接受，通过返回 false 和 OutError 反馈；不会创建处理对象。
世界销毁时一并释放子地图和处理对象；这里不是跨地图持久化流程。

## 已进入主地图后的对象加载流程

这条入口用于游戏运行期间追加或替换子地图，不需要重新调用整图切换，也不需要主地图处在 `LoadSubMaps` 的初始化阶段。

1. 调用 **创建子地图资源处理对象**，选择 `UMTS_SubMapHandler` 蓝图子类。给返回的对象赋值，例如本次进入的小队 ID。
2. 使用 **获取所有子地图** 查看当前注册表；或用 **根据Tag获取子地图ID** 只查询需要替换的区域。
3. 调用 **按请求与处理对象加载子地图**，连接处理对象、`FMTS_SubMapLoadRequest` 和待卸载 ID 数组。数组为空就直接追加，已有其他子地图不受影响。
4. 请求中的“加载界面类”接 `UMTS_MapLoadingWidget` 子类。界面随请求创建，接收独立进度；默认保留 20% 供蓝图初始化使用。
5. Handler 的 **子地图加载完成** 事件表示关卡已可见。在这里生成小队、绑定事件等，按需调用 **更新本子地图加载进度**。结束时调用 **通知本子地图初始化完成**。开启“等待处理对象通知加载完成”时，单独设置 100% 不能代替此通知。
6. 插件将状态设为 Completed，调用 Handler 的 **子地图初始化完成**，进度显示追到 100% 后按配置延迟关闭界面。此事件适合激活玩家、切换地图 UI。显示计时使用真实时间，游戏暂停时也能完成。

整个请求先校验，再卸载指定实例；状态 `WaitingForUnload` 表示正在等待旧实例实际移除，此时还不会开始新地图的预加载。重复 ID、重复使用同一个 Handler、并发前台请求均返回错误。后续异步失败由 Handler 的失败事件和子系统状态事件报告。

### Handler 的卸载生命周期

- 调用 Handler 的 **卸载本子地图**，或者函数库的 **根据ID卸载子地图**。
- **子地图开始卸载**：关卡和 Handler 仍可访问，适合停止活动、解绑或先把玩家送回基地。
- **子地图卸载完成**：引擎已移除关卡；此回调执行期间 Handler 仍可按 ID 查询，回调后从注册表释放。
- 加载途中取消会先调用一次 **子地图加载失败或取消**，随后走卸载清理；**报告本子地图初始化失败** 也会关闭读条并卸载失败实例。

### SilverChoir 的 T5 示例

`WBP_OperationsCommandRoom` 的“请求进入当前瓦片地图”事件创建 `BP_SubMapHandler_T5`，先赋值 `SquadIds`，查询 `Map.Region.Tile`，再提交请求。基地不使用这个标签，因此保留原来的关卡实例。旧批量配置 `FMTS_SubMapLoadConfig` 也新增了 `MapTags`，其他由批量入口加载的瓦片区域同样可以参与查询。

`BP_SubMapHandler_T5.LoadRequest` 配置 `DA_T5Map`（ID 为 T5、地图为 `L_BattleTemplate`）、加载界面 `WBP_MenuLoading` 和放置变换；`LocalEntryTransform` 是相对子地图的玩家进入点。默认放置在 X=100000，与基地隔开。

Handler 完成作战室退出后通知初始化完成，再调用主地图的 `ActivateLoadedMap` 并显式指定战斗地图类型。重复进入已驻留的 T5 会复用同一个 Handler 和关卡。卸载不会自动激活基地；返回基地的业务流程后续实现。

### C++ 通用父类与蓝图职责

`BP_SubMapHandler_T5` 继承项目的 `UGameMainMapSubMapHandler`，后者继承插件的 `UMTS_SubMapHandler`。

- 插件父类提供“获取本子地图信息”“本子地图是否初始化完成”“计算本子地图世界变换”“获取处理对象最近错误”。查询会同时检查对象身份，已卸载的旧 Handler 不能访问后来复用相同 ID 的新实例。
- 项目父类提供“提交子地图进入”“激活本子地图”，统一检查状态、计算局部进入点对应的世界坐标，再调用 GameMainMap。地图切换插件不依赖 SilverChoir 的 GameMode。旧 MapConfig 和“当前子地图激活时返回基地”已移除。
- “切换并等待进入前场景”接收蓝图指定的标签；到达后触发 **进入前场景已就绪**。同一个等待请求可重复调用，不会重复绑定；等待其他场景的并发请求会返回错误。
- C++ 资源清理在失败、卸载、外部移除或世界销毁时自动执行一次，先于蓝图失败/卸载事件。无需在蓝图中调用父函数才能解绑通用场景回调。“取消进入前场景等待”只取消 Handler 的等待，不回滚场景管理器已经接受的切换。

T5 的 `LoadRequest`、`LocalEntryTransform`、`OverviewSceneTag`、`SquadIds` 仍是蓝图变量。蓝图保留以下编排：

1. **子地图加载完成** → `PrepareTileEntry` → **切换并等待进入前场景**。
2. **进入前场景已就绪** → 地图特有初始化（可在此增加小队部署）→ **提交子地图进入**。
3. **子地图初始化完成** → **激活本子地图**。第一次进入由这一步激活；重访已驻留地图时，“提交子地图进入”会直接激活，不重复通知首次加载完成。
4. **子地图开始卸载** 保留为空的地图特有资源清理扩展事件；**子地图卸载完成** → 清理本地图的小队参数。不会隐式传送玩家或切换基地 UI。

节点返回 false 时读取 OutError；“获取处理对象最近错误”也能读取保存的错误。具体提示样式和地图特有清理继续由蓝图决定。

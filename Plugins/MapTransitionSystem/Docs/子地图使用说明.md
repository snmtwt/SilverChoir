# 动态子地图（UE 5.8）

原有子地图节点仍兼容。1.2 新增处理类与进度接口，见 [加载进度与处理类](加载进度与处理类.md)。
新增 `UMTS_SubMapSubsystem` 按当前 World 管理动态关卡实例；整图切换销毁旧 World 时，旧子地图及记录一起清理。

## 配置和加载

1. 内容浏览器 → 杂项 → 数据资产 → 选择 `MTS 子地图数据资产`（`UMTS_SubMapDataAsset`）。
2. 填写地图地图（World 软引用）、地图ID（FName）、地图名（FName）、地图Tags（GameplayTagContainer，可多个或留空）。前三项必填。
3. 在项目 Gameplay Tags 设置中注册需要的标签，例如 `Map.Tavern.Room`。
4. 蓝图调用“加载子地图”，传入数据资产、Location 和 Rotation。零位置、零旋转表示保留地图原始坐标。
   位置单位为 UE 厘米，旋转作用于整个关卡。父地图保持运行，不替换 GameMode、控制器或 HUD。
5. 返回 true 表示请求已接受；false 时读取 OutError。通过“获取子地图子系统”绑定“子地图状态变化”，
   等待 State=Loaded 才表示加载且显示完成。应在发起请求之前绑定事件。

子地图使用 `ULevelStreamingDynamic::LoadLevelInstanceBySoftObjectPtr` 异步加载，不弹出原整图切换的加载界面。
Loading/Loaded/Unloading/Unloaded/Failed 分别表示加载、显示、卸载请求、实际移除、异步失败。对象加载入口还支持 WaitingForUnload，等待指定旧子地图实际移除后开始新加载。
同步参数校验失败仅通过返回值和 OutError 报告；异步失败通过状态事件的 Error 报告。

## 查询与卸载

### 按 Key 管理显隐

插件在当前 World 的子系统内自动保存通过它加载的实例，无需再次注册。
**Key 就是数据资产的 MapID（FName）**，例如当前基地的 Key 为 `Base`；不用地图名、资源路径或 MapName。
此为运行时注册表，不是磁盘存档。隐藏保留记录和关卡资源，卸载完成或主世界销毁才清理。

- **根据Key获取子地图**：返回是否找到及信息结构，包括 StreamingLevel、State、实际 `bIsVisible` 和请求 `bShouldBeVisible`。不存在时清空输出。
- **根据Key隐藏子地图 / 根据Key显示子地图**：只修改流式关卡可见性，不重新加载、不卸载。重复设置同一状态可安全调用。
- **根据Key设置子地图显示**：同一操作的布尔参数版本。
- **子地图实际可见性变化**：在子系统上绑定此事件，等待引擎实际应用隐藏/显示；节点返回 true 只代表请求被接受。

仅允许初始化进度已 Completed 且 State=Loaded 的关卡修改显隐。加载中/卸载中/不存在的 Key 返回 false 和错误说明，避免破坏首次显示及统一加载进度。
隐藏后 State 仍为 Loaded；判断是否显示请读取 bIsVisible，不能仅根据 State 判断。
首次加载完成继续使用原有状态事件，后续显隐使用独立事件，不重复发送加载完成回调。
仅隐藏不等同于暂停游戏逻辑，也不提供存档或战斗快照保证。AI、计时器、音效等活动管理仍在项目蓝图中处理。

所有节点位于“地图切换 | 子地图”，函数库自动解析当前世界，也可直接调用子系统方法。

| 蓝图节点 | C++ 方法 | 行为 |
|---|---|---|
| 获取所有子地图 | GetSubMaps | 返回元数据、变换、状态和 StreamingLevel |
| 获取所有子地图ID | GetAllSubMapIDs | 返回当前记录中的所有唯一 ID |
| 获取所有子地图名 | GetAllSubMapNames | 每实例一个名称，允许重名 |
| 根据Tag获取子地图 | GetSubMapsByTag | 返回全部匹配的子地图信息 |
| 根据Tag获取子地图ID | GetSubMapIDsByTag | 返回匹配的实例 ID，适合传入新请求的待卸载列表 |
| 根据ID获取子地图处理对象 | GetSubMapHandler | 返回驻留 Handler，直到实际卸载完成后释放 |
| 根据ID卸载子地图 | UnloadSubMapByID | 返回是否新接受卸载请求 |
| 根据名称卸载子地图 | UnloadSubMapsByName | 卸载全部同名实例，返回新发起卸载的数量 |
| 根据Tag卸载子地图 | UnloadSubMapsByTag | 卸载全部匹配实例，返回新发起卸载的数量 |

- 查询包含 WaitingForUnload、Loading、Loaded、Unloading；如只需要完成初始化的地图，筛选 State=Loaded 且 LoadingPayload.Phase=Completed。返回顺序不保证稳定。
- 仅包含通过本插件子地图接口创建的实例，不枚举地图编辑器中已有子关卡或 World Partition 网格单元。
- 同一 ID 在同一 World 内只能存在一次，直到实际卸载完成后才可重新使用。不同 ID 可以加载同一地图的多个实例。
- 名称使用 FName 比较（不区分大小写），允许重复；不作为本地化显示文本。
- Tag 默认支持层级匹配：查询 `Map.Tavern` 会匹配带 `Map.Tavern.Room` 的实例；Exact Match=true 时必须标签完全一致。
- 卸载可取消加载中的地图。重复卸载返回 false/0；子系统广播 Unloaded 状态时记录已移除，可以重新加载该 ID。Handler 的“子地图卸载完成”回调在移除注册表之前执行，便于最后清理。
- 元数据在加载时复制，运行中编辑数据资产不会修改已有实例。

## 适用范围

使用适合动态流式加载的普通关卡制作子地图；本实现未验证 World Partition 地图、嵌套关卡或联网复制。
接口操作当前进程中的 World，不自动向客户端同步加载请求、实例命名和卸载请求。
打包时需将动态加载的地图加入 Packaging → List of Maps to Include，或使用项目已有的 Asset Manager Cook 规则。
流式加载不会启用子地图的 GameMode；地图内不要放置不希望重复生成的全局管理 Actor。

# 用配置数组加载子地图

在地图处理蓝图的 `OnMainMapLoaded`（主地图加载完成）事件中，从 TransitionSubsystem 调用 **按配置数组加载子地图 / LoadSubMaps**。
传入 `MTS Sub Map Load Config` 结构体数组；可提升为蓝图变量，在类默认值中配置。

| 字段 | 用途 |
| --- | --- |
| MapID | 当前 World 中唯一的 ID，同时是后续查询、隐藏、显示的 Key |
| Weight | 正数，分配剩余加载进度的相对权重 |
| MapAsset | 要加载的普通地图软引用 |
| Location | 地图实例在宿主世界中的位置，单位 cm |
| Rotation | 地图实例在宿主世界中的旋转 |

一次调用会先校验全部配置、登记统一进度计划，再并行发起加载。同一地图可用不同 ID 和位置创建多个实例。
返回 true 仅表示请求已接受；完成以 **OnSubMapsLoaded（全部子地图加载完成）** 为准。
空数组、重复或已使用 ID、无效地图、非正权重、无效变换都会拒绝。
本节点用于正在进行的整图切换：主地图已加载，启用“需要主动通知加载完成”，且尚未登记其他子地图计划。
独立运行时的单地图加载仍可使用原有子地图加载节点；不要重复提交同一批数组。

## 进度与关闭时机

切换地图时 AutomaticProgressMax 设为 0.3，启用主动通知，关闭延迟设为 1 秒。
总进度 = 0.3 + 0.7 × Σ(子地图进度 × 权重) / Σ权重。
例如权重 2 和 1 的两个子地图，分别占总进度约 46.67% 和 23.33%。并行加载时会同时贡献进度。
这是阶段进度，并非磁盘字节进度。达到 100% 不会代替业务完成通知。

在 OnSubMapsLoaded 中完成玩家安置等业务，再调用 **通知地图加载完成 / NotifyMapLoadCompleted**。
插件从通知后开始计时，1 秒后关闭界面；无需再接 Delay。
提前通知会等待所有子地图 Completed。异步失败或取消会终止本次加载，并请求卸载本批实例。
同步返回 false 时，蓝图接 **报告地图初始化失败**，避免加载页一直等待。
完成后实例继续保留在当前 World 的子地图子系统中；按 MapID 查询、显示、隐藏或卸载。

## SilverChoir 蓝图

`/Game/System/Map/MainMenu/MapTransitionHandler/BP_MapTransitionHandler_NewGame`

- 类默认值 **SubMapConfigs**：默认一项 Base，权重 1，地图 L_BaseTemplate，位置与旋转为零。
- 主地图加载完成 → 按配置数组加载子地图 → Branch，失败连接报告地图初始化失败。
- 全部子地图加载完成 → Get GameMode / Cast → ActivateLoadedMap(Base, 玩家世界进入点) → 通知地图加载完成。
- ActivateLoadedMap 只更新活动地图和安置玩家，不加载地图。示例玩家进入点为世界坐标 (0,0,200)，与地图实例位置分别配置。
- ReturnToBase 已删除；添加子地图只需扩展数组，不需要另写 C++ 加载流程。
- 直接 PIE 启动 GameMainMap 不再自动加载基地，需要蓝图主动安排加载。

原来的 ConfigureSubMapProgressPlan 保留，供需要自定义串行加载/子地图处理类的流程使用；不要与数组节点重复登记计划。
蓝图修改前备份位于 Saved/NewGameHandlerBackups。
新增地图须加入 Packaging/Asset Manager 的 Cook 配置。

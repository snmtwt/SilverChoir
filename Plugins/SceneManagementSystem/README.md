# Scene Management System

Map 是地图资源及其加载容器；Scene 是地图内部的功能状态，例如基地总览、建造、编队或战斗部署。本插件只管理 Scene 生命周期，不自动加载、显示或卸载地图。地图工作继续使用 MapTransitionSystem。

## 四件套

| 类 | 职责 |
| --- | --- |
| SMS_SceneSubsystem | World 子系统，创建并持有管理器 |
| SMS_SceneLibrary | 蓝图函数库：按 Tag 切换、获取当前对象/Tag、完成通知 |
| SMS_SceneSettings | 项目设置 → 插件 → 场景管理系统，指定管理类 |
| SMS_SceneManager | 管理类，配置场景类列表，持有实例并执行切换状态机 |

额外的 `SMS_SceneBase` 是每个功能场景的 UObject 蓝图基类。

## 蓝图配置

1. 新建继承“功能场景基类 / SMS_SceneBase”的蓝图，例如 BP_Scene_BaseOverview、BP_Scene_Construction。在类默认值填写 SceneTag。先在项目 Gameplay Tags 设置中注册所需标签，例如 `Scene.Base.Overview` 和 `Scene.Base.Construction`。
2. 重写“进入场景”和“离开场景”。进入函数参数 PreviousSceneTag 是上一场景；离开函数参数 NextSceneTag 是目标场景。首次进入的 PreviousSceneTag 为空。
3. 在 `BP_SceneManager` 类默认值的“场景类列表”添加这些蓝图类。管理器读取各类默认值上的 SceneTag，使用精确匹配，不使用父标签匹配；空标签、重复标签、空类和抽象类会使配置校验失败。
4. 在项目设置中选择 BP_SceneManager。SilverChoir 已在 `/Game/System/SubSystem/SceneSystem/BP_SceneManager` 创建空管理类并配置好，场景列表留给项目填写。
5. 任意有 World 上下文的蓝图调用“按标记切换场景”。可以从区域块的“区域被点击”重写事件中调用此节点。

## 返回值与异步完成

- 进入/离开函数返回 true：该步骤已经完成，管理器立即执行下一步。
- 离开返回 false：当前对象继续保留，目标对象存入待进入状态；稍后在旧场景自身调用“通知离开场景完成”，才释放旧实例并进入目标场景。
- 进入返回 false：新实例成为当前对象，但状态为“等待进入完成”；稍后由新场景自身调用“通知进入场景完成”，切换才完成。
- 蓝图带返回值的函数不能直接放 Delay。可在函数中启动自定义事件、动画、计时器或其他异步操作，然后返回 false；异步回调中通知完成。
- 从其他对象通知时，使用函数库的“通知指定场景离开完成/进入完成”，传入当次参与切换的场景实例。不要在迟到的回调中重新获取当前对象冒充旧实例。过期对象、错误阶段和重复通知会被拒绝。
- 在进入/离开函数内部立即通知完成也受支持；管理器会等待该函数返回后再推进，避免嵌套执行下一场景回调。

“切换场景”返回 true 仅表示请求已被接受。通过“获取场景切换状态”判断是否仍在等待，或绑定管理器的“场景切换完成 / OnSceneChanged”。此事件仅在进入完成时触发，携带上一场景与当前场景的 Tag。

## 查询、持有和边界

- 没有场景：当前对象为空、当前 Tag 无效、状态空闲。
- 等待离开：当前对象/Tag 仍为旧场景，待进入 Tag 为目标场景。
- 等待进入：当前对象/Tag 已是新场景，待进入 Tag 为空；进入完成后状态变为空闲。
- 空闲时重复切换到当前 Tag：返回 true，不重新调用生命周期函数，不重建对象。
- 忙碌时的新请求和生命周期/完成事件中的重入请求：返回 false，不覆盖目标；需要连续切换时，请在回调返回之后调用，例如下一帧。
- 管理器持有当前和待进入实例，防止垃圾回收。退出后释放旧引用；再次进入同类时创建新实例。其他蓝图若保留旧对象引用，应自行清理。
- 子系统属于 Game/PIE World。流式地图共享常驻 World 的同一管理器；OpenLevel 或结束游戏会清理管理器，取消等待，不再调用异步退出步骤。场景自行创建的 Actor、UI、定时器等应在离开逻辑中清理。
- 此版本是本地场景状态管理，不自动复制到网络客户端。

## 验证

自动化测试前缀 `SceneManagementSystem` 保留配置校验、World 子系统和函数库检查。测试场景类及其原生 GameplayTag 已移除，插件不注册测试标签。
